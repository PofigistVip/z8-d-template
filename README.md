# Z8 D Template

Шаблон приложения Z8 на D, основанный на `z8-template`. BL-исходники моделей,
представлений и настройки доступа, а также клиентские JavaScript, CSS и HTML
сохранены из исходного шаблона. Компилятор и runtime подключаются из `z8-d`.

## Сборка

Нужны Python 3, DMD, DUB, C-компилятор, клиентские библиотеки PostgreSQL,
собранный `z8d` и исходное дерево `z8-d`. Стандартные BL и ресурсы веб-клиента
берутся из `z8-d/vendor/z8`; исходный Java-проект для сборки не требуется.

В PowerShell из каталога шаблона:

```powershell
python build.py --z8-d C:/path/to/z8-d --postgres-bin 'C:/Program Files/PostgreSQL/15/bin'
```

Вместо параметра `--z8-d` можно установить `Z8_D_ROOT`. Для совместимости
`--original-z8` позволяет явно выбрать другое дерево исходных BL и web-ресурсов.
Каталог PostgreSQL определяется через `--postgres-bin`, `Z8_PG_BIN` или
`pg_config`. Сборка создаёт `build/z8-template.exe` (в Unix — `build/z8-template`),
клиент в `build/public` и сгенерированные D-модули в `build/generated`.
В `build/generated` находятся только модули приложения. Модули ядра BL
собираются в отдельную библиотеку `z8-d/build/libraries/core` и переиспользуются
при следующих сборках. При изменении исходников ядра, runtime, компилятора или
DMD библиотека пересобирается автоматически. Для подключения уже собранного
ядра укажите `--core-library <каталог-библиотеки>`. Дополнительные BL-библиотеки
подключаются повторяемым параметром `--library <каталог-библиотеки>`; их
зависимости тоже нужно перечислить. Формат и сборка библиотек описаны в README
`z8-d`.
При связывании проверяется версия DMD, указанная в манифесте каждой библиотеки;
при несовпадении библиотеку требуется пересобрать.
При каждой сборке каталоги `build/generated` и `build/public` пересоздаются;
не храните в них собственные изменения. Временные объектные файлы и библиотеки
создаются внутри `build/generated` и удаляются после сборки.
В Windows каталог `bin` PostgreSQL должен находиться в `PATH` при запуске.

## Запуск

Заранее создайте базу и схему, в которой пользователь подключения может создавать
таблицы. В каталоге проекта выполните:

```powershell
$connection = 'host=127.0.0.1 dbname=z8 user=z8 password=z8'
./build/z8-template.exe $connection public --initialize
# Установите пароль Admin в SystemUsers, как описано ниже.
./build/z8-template.exe $connection public
```

При `--initialize` запускается генератор схемы приложения, в том числе его BL-хуки
настройки прав и меню. Для администратора задайте пароль в `SystemUsers`: поле
`Password` содержит MD5 пароля в представлении, ожидаемом Z8. Например, для
локальной базы можно выполнить `UPDATE "SystemUsers" SET "Password" = md5('пароль')
WHERE "RecordId" = '00000000-0000-0000-0000-000000000002'`. Используйте собственные
учётные данные.

Адрес и порт сервера задаются в `server.properties` свойствами
`web.server.http.host` и `web.server.http.port`; в шаблоне это
`127.0.0.1:9080`. Клиент находится в `build/public`.
Доступны обычная страница `index.html` и страница отладки `debug.html`.
Путь к клиенту можно изменить через `--public-dir`, файл настроек — через
`--config`. Для локальных настроек, которые не попадут в Git, можно использовать
`--config server.local.properties`. Если `--config` не задан, при
наличии загружается `server.properties` из текущего каталога. Для остановки
нажмите Enter в консоли сервера.

## Интеграционная проверка

После сборки тест создаёт временный экземпляр PostgreSQL, запускает сервер и
проверяет вход, меню, документы, историю, фильтр и загрузку файла:

```powershell
python tests/e2e.py --z8-d C:/path/to/z8-d --postgres-bin 'C:/Program Files/PostgreSQL/15/bin'
```

Сборку и те же сценарии без обращения к исходному Java-проекту можно проверить
во временной копии шаблона командой `python tests/build_without_original.py`
с теми же параметрами `--z8-d` и `--postgres-bin`.
Для проверки хранения вложений на диске перед запуском установите
`$env:Z8_TEST_FILES_ON_DISK = "1"`. Для проверки преобразования документов и
писем в PDF также задайте `$env:Z8_TEST_OFFICE_HOME` каталогом LibreOffice.

Реализация `z8-d` и совместимость всех функций исходного шаблона ещё развиваются;
успешная сборка сама по себе не подтверждает полную эквивалентность.
# Экспорт таблиц

Команда клиента «Microsoft Excel (*.xls)» создаёт файл Excel в формате XLSX
с расширением `.xlsx`. Экспорт учитывает фильтры и права текущего пользователя.
Ширины колонок переводятся в единицы Excel приблизительно.
Форматы запроса `doc` и `docx` формируют документ Word `.docx`.
Формат `html` создаёт отдельный HTML-файл с таблицей данных.
PDF создаётся со шрифтом Roboto из оригинального Z8 и поддерживает кириллицу;
параметр `options` позволяет задать `pageFormat`, `pageOrientation` и поля в миллиметрах; `detailRowHeight` и `detailVertAlign`
задают высоту и выравнивание строк.
Ширина столбцов масштабируется по `width` и `minWidth`; длинные значения обрезаются по границам столбцов. Оформление отчётов BIRT
пока не воспроизводится.
